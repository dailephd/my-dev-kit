SUMMARY
-------
v1.2.0 adds React/TSX and frontend-test semantic indexing, exact source
retrieval with repeated literal reporting, React region retrieval, local
component-tree prop/event-flow retrieval, and four new frontend semantic
graph views. All v1.1 data-model, code graph, search, lookup, slice, source,
and view capabilities remain unchanged.

---

HIGHLIGHTS
----------
- Run `index` on a project with TSX/JSX files and get `frontend-semantic.json`
  automatically — no extra flags required.
- Find exact UI strings (data-testid, aria-label, literal values) across all
  indexed files with surrounding context:

    npx @dailephd/my-dev-kit source --index .my-dev-kit \
      --contains "workspace-editor-empty-state" --context 5 --format numbered

- Retrieve a named React component, hook, handler, or JSX region by name:

    npx @dailephd/my-dev-kit source --index .my-dev-kit \
      --react-region WorkspaceEditorShell \
      --file "src/WorkspaceEditorShell.tsx" --format numbered

- Retrieve a component and its local child components as a connected source
  bundle, including prop assignments, event handlers, state accesses, and
  JSX branches:

    npx @dailephd/my-dev-kit source --index .my-dev-kit \
      --symbol WorkspaceEditorShell \
      --file "src/WorkspaceEditorShell.tsx" \
      --include-local-component-tree --format numbered

- Render four frontend semantic graph views backed by frontend-semantic.json:

    npx @dailephd/my-dev-kit view --index .my-dev-kit \
      --graph react-component --format dot \
      --out .my-dev-kit/react-component.dot

    npx @dailephd/my-dev-kit view --index .my-dev-kit \
      --graph react-flow --format dot \
      --out .my-dev-kit/react-flow.dot

    npx @dailephd/my-dev-kit view --index .my-dev-kit \
      --graph react-prop-event-flow --format dot \
      --out .my-dev-kit/react-prop-event-flow.dot

    npx @dailephd/my-dev-kit view --index .my-dev-kit \
      --graph frontend-test --format dot \
      --out .my-dev-kit/frontend-test.dot

NEW SOURCE FLAGS
----------------
--contains <string>
    Exact string search across all indexed source files. Returns all matches
    with context lines, match classification (declaration-like, usage-like,
    unknown), and frontend value context when the string appears in frontend
    facts. Reports repeated occurrences across files.

--context <n>
    Number of context lines to include around each --contains match.

--path <prefix>
    Filters --contains results to files matching a path prefix. Rejects path
    traversal.

--react-region <name>
    Retrieves the source range of a named React region (component, hook,
    handler, JSX region, prop type) from the frontend semantic artifact.
    Requires --file. Mutually exclusive with --contains, --symbol, --node,
    --start/--end.

--include-local-component-tree
    When used with --symbol, retrieves the component and all its local child
    components as a connected source bundle. Includes prop assignments,
    callback invocations, event handlers, state accesses, JSX branches,
    prop references, and prop type blocks.

--prop <name>
    Filters --include-local-component-tree output to blocks referencing a
    specific prop name.

---

NEW GRAPH CHOICES
-----------------
react-component
    Static React component graph showing exported components, local
    (non-exported) components, prop type interfaces, and their structural
    relationships.

react-flow
    All frontend flow facts: components, local components, prop types, hooks,
    handlers, JSX regions, and flow relationships. Useful for full-file
    frontend structure review.

react-prop-event-flow
    Only prop and event flow relationships between components. Excludes hook
    and handler detail nodes.

frontend-test
    Frontend test structure: test files, describe blocks, test/it blocks,
    setup/teardown hooks, locator expressions, and route-like strings. Requires
    test facts to have reached the frontend analyzer (see Known Limitations).

All four graph views are backed by frontend-semantic.json and do not require
Graphviz for DOT output.

---

NEW ARTIFACTS AND ANALYZER BEHAVIOR
-------------------------------------
frontend-semantic.json
    New artifact written when the index command encounters TSX or JSX files.
    Contains: exported React components, local (non-exported) React components,
    prop type interfaces, hook blocks (useState, useEffect, and others), event
    handlers, JSX regions, render helper functions, test blocks (describe, test,
    it), setup/teardown hooks, locator expressions, route-like strings, and
    important UI strings (data-testid, aria-label).

    Registered in manifest.json under semanticArtifacts.frontendSemantic.

search enrichment
    The search command now indexes frontend semantic values (data-testid,
    aria-label) as an additional signal. Files with matching frontend values
    rank alongside files with matching symbol names.

COMPATIBILITY NOTES
-------------------
- All v1.1 commands (index, search, lookup, slice, source, view, data-model)
  continue to work without change.
- v1.1 index artifacts (manifest.json, symbol-index.json, code-graph.json,
  data-model.json, data-model-graph.json, model-view-lineage.json) are
  unchanged.
- The frontend-semantic.json artifact is additive. Projects without TSX/JSX
  files will not produce this artifact and are not affected.
- v1.1 graph choices (code, data-model, model-view-lineage) are unchanged.

KNOWN LIMITATIONS
-----------------
Static analysis only
    All React/TSX analysis is conservative static extraction from source text.
    frontend-semantic.json records what the static analyzer found; it does not
    prove what the application renders at runtime.

No runtime React behavior
    Route-aware reachability, browser-state tracing, and UI visibility analysis
    are not supported. Dynamic component registrations, runtime-composed JSX,
    and computed prop names may not be extracted or may be partially extracted
    with warnings.

Frontend-test indexing gap
    The base indexer excludes files matching .test. and .spec. patterns by
    default. view --graph frontend-test produces output only when test files
    reach the frontend analyzer through a custom indexing path that does not
    use the default exclusion patterns.

Symbol end-line not recorded
    Source retrieval by symbol returns a capped preview from the symbol's start
    line with a warning. Use explicit line ranges for exact bounds.

No source continuation or source bundles (planned v1.4)
No context capsules or planner packets (planned v1.5/v1.6)
No hosted service, LLM calls, or network requests
No automatic source-code editing

UPGRADE NOTES
-------------
Users upgrading from v1.1 do not need to change existing commands or
artifacts. Re-running `index` on projects with TSX/JSX files will produce
frontend-semantic.json automatically.

Users on v1.1 who want to try v1.2 locally without publishing:

    # From the repository root
    npm run build
    node dist/cli.js index --root . --src src --out .my-dev-kit --json
    node dist/cli.js source --index .my-dev-kit --contains "YourString" --context 5 --format numbered
