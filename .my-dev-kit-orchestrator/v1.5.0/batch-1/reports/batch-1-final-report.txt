Summary of classification contract decision:
- New artifact: classification.json, schemaVersion '1.0.0', registered as a
  generic analyzer entry (IndexAnalyzerId 'classification') in manifest.json's
  existing analyzers[] list - no change to the fixed-shape
  IndexSemanticArtifacts interface.
- Compact refs: two NEW optional fields, `classificationRoles` and
  `classificationRefs`, added to CodeGraphNode and GraphSymbolRecord -
  explicitly NOT reusing/overloading the existing `semanticRoles`/
  `artifactRefs` fields, per the task's own instruction not to silently
  overload existing semantic fields. Category NAME strings are still reused
  verbatim where v1.1/v1.2's SemanticRoleName already covers a category
  (11 of 13 required categories already exist there), avoiding vocabulary
  drift while keeping storage independent.
- Evidence/uncertainty model mirrors the shape (not the exact type) of the
  existing SemanticEvidenceRef/SemanticRoleWarning/SemanticRoleConfidence
  types, with a distinct UncertaintyTier enum ('certain'|'likely'|'possible'|
  'unknown') chosen because it measures a different axis (confidence in
  correctness) than the existing SemanticRoleConfidence enum (how a role was
  derived).
- Enrichment pattern mirrors applySemanticRolesToCodeGraph /
  applySemanticRolesToSymbolIndex exactly (map-by-id, same node.kind guard).
- Command integration (search/lookup/slice/source surfacing classification)
  is explicitly deferred past this batch; a forward-looking contract for it
  is documented in classification-contract.txt section 8 for a later batch.
