===============================================================================
Uncovered test responsibilities and reasons
===============================================================================

- TST-020 (graph-renderer/report-renderer): intentionally uncovered,
  unchanged from Batch 1's explicit deferral (behavior-model.txt BEH-022).
- TST-050 through TST-053 (search/lookup/slice/source command-output
  integration): intentionally uncovered, explicitly Batch 3 scope per this
  task's non-goal list. The local CLI smoke test in this batch's
  verification stage DID confirm search/lookup/slice do not crash and that
  lookup/slice already surface the compact fields as raw node-object
  properties (no formatting/summarization) - this is the producer-side
  minimum the task asked for ("must not crash"), not the Batch 3 output-
  formatting work itself.
- TST-070 (classification analyzer failure reported as manifest status
  'failed', not a thrown/uncaught exception): the PRODUCTION code path
  exists (runClassificationAnalyzer's try/catch in runIndexCommand.ts,
  documented in the implementation report), but no test exercises the catch
  branch. Honest reason: this batch's classification producer only reads
  already-in-memory, already-validated artifacts (the same dataModel/
  frontendSemantic/frontendReachability objects the index command just
  built in the same process) rather than re-parsing untrusted JSON from
  disk - there is no reachable "malformed upstream artifact" input in this
  integration shape that would make buildClassificationArtifact() throw
  without also making one of the *existing* v1.1-v1.4 analyzers fail first
  (in which case that analyzer's own existing failure-mode test coverage
  applies, not classification's). Fabricating an artificial throw via test-
  only code injection was rejected as not representative of real behavior.
  This is flagged honestly rather than claimed as covered.
- TST-071 (classification absence does not break search/lookup/slice/source
  output shape): explicitly deferred by test-strategy-packet.txt itself to
  whichever batch first modifies those commands (Batch 3) - unchanged.
