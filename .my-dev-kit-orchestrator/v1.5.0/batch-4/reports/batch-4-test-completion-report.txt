Remaining uncovered risks
===============================================================================

- TST-070 (classification analyzer failure reported as manifest status
  'failed', not a thrown/uncaught exception): STILL not covered by a
  dedicated test, unchanged from Batch 2's honest disclosure. The
  production code path exists (try/catch in runClassificationAnalyzer,
  src/indexing/runIndexCommand.ts) and this batch's new
  classificationGracefulDegradation.spec.ts tests the CLOSELY RELATED and
  more realistic scenario (missing optional artifacts, which is the actual
  reachable failure mode in this integration shape), but does not directly
  trigger buildClassificationArtifact() to throw. No realistic external
  input can make it throw without one of the *existing* v1.1-v1.4 analyzers
  already having failed first (since classification only reads already-
  validated in-memory objects, never re-parses untrusted JSON from disk in
  this integration design) - fabricating an artificial throw via test-only
  code injection would not represent real behavior and was rejected as
  before. This remains an honestly-disclosed, deliberately-scoped gap, not
  an oversight.
- TST-020 (graph-renderer/report-renderer categories): unchanged, still
  correctly deferred per Batch 1's own decision (BEH-022) - no new evidence
  was found in this batch's gap review that would justify adding these
  categories now.

===============================================================================
Why these test responsibilities were intentionally deferred
===============================================================================

Both remaining gaps (TST-020, TST-070) were deferred for the same reason in
every batch that touched them: adding them now would require either (a)
inventing categories with no concrete static evidence (TST-020, which would
violate BEH-011's conservative/evidence-backed constraint), or (b)
fabricating an unrealistic test scenario that doesn't correspond to any
actual reachable code path in the current integration design (TST-070).
Both are documented, not hidden, and neither affects any of the behavior
this batch's docs describe as implemented.
