MANDATORY FILE-PLACEMENT DECISION
---------------------------------
A. Source implementation or contract? Extend the existing src/<owner>/ file/module. Search before creating new source files.
B. Command registration? src/commands/ and existing src/cli.ts; implementation logic stays in its specific subsystem.
C. Indexed artifact or schema? Extend the existing symbol-index/graph/indexing owner; no parallel artifact or graph family.
D. Retrieval quality/ranking? src/search/; share only safe generic predicates with src/context/ where justified, not Android policy wholesale.
E. Source slices/cursors? src/lookup/; presentation/source bundle behavior belongs in src/source/.
F. Regression test? Closest existing tests/<owner>/, with deliberate fixtures in tests/fixtures/ and durable benchmark configuration in benchmarks/retrieval/.
G. Product or maintainer docs? Edit the established docs owner; never create a near-duplicate summary or delete historical sections.
H. Generated index, benchmark run, analysis output? Use an explicitly approved ignored existing output owner, never src/, tests/, benchmarks/, docs/, dev/ or the root by convenience.
I. New directory? Prove no owner exists, why an existing directory fails, what exact files it would hold, closest tests, public/private exposure, and explicit scope approval first.
