# Retrieval regression suite (v1.7)

This directory holds config for `my-dev-kit`'s internal, developer-facing
retrieval regression suite. Batch 1 introduced the foundation; Batch 2
added the execution core; Batch 3 adds assertion-based regression judgment.

## What this is

- A local, deterministic config format describing retrieval regression
  tasks for `my-dev-kit`'s own context-capsule workflow (query planning,
  candidate ranking, focus selection, graph/source evidence, metadata
  summaries, conflict detection, mode behavior, `--no-source`, adequacy,
  audit completeness), each with optional `expectations` evaluated
  against the task's generated evidence.
- Run via `npm run benchmark:retrieval` from the repository root.
- Each non-skipped task is actually executed: its fixture/source roots
  are resolved, a fresh local index is built, the real v1.6 `context`
  command runs against it, producing `context-capsule.json`,
  `retrieval-audit-record.json`, and a `task-execution.json` execution
  record, and (as of Batch 3) the task's configured `expectations` are
  evaluated against that generated evidence to produce assertion
  results, metrics, and a `PASS`/`REGRESSION`/`BLOCKED` verdict.
- Maintainer/developer tooling, not a public CLI command.

## What this is not

- Not `my-dev-kit-lab`. It does not perform release readiness, security,
  dependency, or package-content validation.
- Not a hosted or public benchmark service.
- Not wired into `npm run verify` or CI. It remains a separate maintainer
  check because it is heavier than unit validation and the broader test
  suite has known unrelated timeout flakiness.
- Not a performance benchmark, historical baseline comparison, security
  check, release gate, package audit, browser/runtime check, or LLM
  evaluation.

## core.json

`core.json` contains six executable tasks using the existing
`basic-data-model-ts`, `basic-react-tsx`, and `basic-ts` examples. Coverage
includes data-model feature-add, subsystem mode, no-source behavior,
React/TSX retrieval, no-false-conflict behavior, ambiguity, audit
completeness, no-raw-content, and cap compliance. Classification-absent
compatibility remains unit-tested and deferred as an executable core task:
current indexing always emits classification, and the runner intentionally
does not mutate generated artifacts.

Expectations use top-K/path presence, maximum caps, required audit steps,
and allowed adequacy status sets rather than exact generated arrays,
durations, timestamps, or machine paths.

## Running it

```sh
npm run benchmark:retrieval
```

This does not require a prior `npm run build` - it runs directly from
TypeScript source via `tsx`, the same mechanism the existing `npm run dev`
script already uses. The context command itself is also invoked via `tsx`
(as a subprocess), so no build step is required anywhere in the pipeline.
The script passes `--fail-on-regression`, so it exits nonzero if the suite
regresses or is blocked.

Other supported flags on the underlying entry point
(`src/retrievalRegression/runRetrievalRegression.ts`):

- `--config <path>` / `--out <dir>` - override the config and output paths.
- `--fail-on-regression` - exit nonzero when the suite verdict is
  `REGRESSION` or `BLOCKED` (an invalid config or a failure to write the
  report is always nonzero, regardless of this flag).
- `--max-failures <n>` - stop running remaining tasks once `n`
  blocked/regressed tasks have accumulated; remaining tasks are recorded
  as `planned` with a clear reason, and `options.maxFailuresReached` is
  set in the report.

Output is written to `.my-dev-kit/retrieval-regression/` by default:

- `retrieval-regression-report.json` / `.txt` - suite-level summary,
  assertion results, metrics, verdict, and per-task status/artifact paths
  (never raw source, graph, capsule, audit, semantic, or classification
  content).
- `tasks/<task-id>/index/` - a fresh local index built for that task's
  fixture (never written into the fixture itself).
- `tasks/<task-id>/context-capsule.json` and
  `tasks/<task-id>/retrieval-audit-record.json` - real v1.6 artifacts
  generated by running the actual `context` command.
- `tasks/<task-id>/task-execution.json` - a compact execution record
  (status, exit code, duration, command arguments).

This directory is local, generated, and gitignored.

The suite is representative rather than exhaustive. It makes no network or
LLM calls, does not execute applications, and does not edit fixture source.
